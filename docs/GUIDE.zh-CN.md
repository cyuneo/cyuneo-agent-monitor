## 功能

### 像终端一样的面板

![底部面板里的智能体监视器标签页，数据是虚构的示例：左边是选中的 Claude Code 聊天窗口的主智能体、两个子智能体和一个工作流的智能体，右边是打开中和最近的聊天窗口列表](../images/split-view.png)

- **智能体监视器**（英文界面为 Agent Monitor）作为一个标签页出现在底部面板，就在终端旁边，看起来也和终端一样：一个整体面板，没有额外的视图标题栏。选中聊天窗口的智能体占了面板的大部分，一列窄的聊天窗口列表放在一侧，就像终端的标签列表。
- **聊天窗口列表。** 每一个打开中和最近的聊天窗口，各带一个状态灯。它们分成 **打开中**（Claude Code 还开着这个聊天，或者 Codex 或 GitHub Copilot Chat 正在一轮对话中）和 **最近**。行高和终端标签一样，选中的聊天窗口会高亮。为了给标题留出地方，每一行只有状态灯和标题；当上下文较大、值得处理时，标题后面会加一个小标记：**◔** 建议考虑压缩，**◕** 建议尽快处理。把鼠标停在行上可以看到状态、上下文等详情。
- **列表在终端标签列表所在的那一侧**（默认右侧，跟随 `terminal.integrated.tabs.location`）；也可以自己设置 `agentMonitor.sessionListPosition` 放在左边或右边。拖动分隔线可以调整宽度，双击分隔线恢复到默认的 200px，或者把它拖到快关上，收成一条只显示状态灯的窄条。面板窄于 500px 时会自动用窄条。宽度会被记住。
- **把鼠标停在聊天窗口上**会出现 **压缩…** 按钮（上下文达到 20K 或以上）和一个 **…** 按钮，里面是和右键菜单一样的操作。也可以用键盘：方向键、Home、End 在列表里移动，Enter 或空格选中，输入文字可以按首字母跳转到某个聊天窗口，Shift+F10 打开操作菜单。
- **智能体。** 点击一个聊天窗口，就能看到它里面正在跑什么：最上面是主对话，然后是子智能体和后台智能体，工作流智能体则按工作流分组显示。
- **聊天窗口的标题区只占两行**，面板矮也能直接看到智能体。第一行是标题，**转到** 和 **压缩…** 旁边写着上下文用了多少（"上下文 41%"）；第二行是状态、上下文离自动压缩还有多远、提示、缓存倒计时和这个聊天的费用。其余内容（上下文进度条、自动压缩设置、今日合计、提示、续跑提示、记录文件那一行）收在 **详情 ▸** 里。遇到额度中断、接口报错、压缩循环这类紧急情况，才会多出一行。智能体表的表头在滚动时固定在顶部；面板矮于 400px 时，费用和用时两列会隐藏。
- 当你切换到 Claude Code 或 Codex 的聊天标签页时，列表里会自动选中对应的聊天窗口。这只会在你切换标签页时发生，绝不会在刷新时发生，所以你的选择不会被打断。
- 侧边栏里还有一个 **总览** 树，状态栏有一个带计数的状态灯，还有一个角标显示有多少聊天窗口需要看一眼。

### 状态灯

同样的六种灯在各处保持一致：会话列表、智能体表格、总览、状态栏和终端版。

| 颜色 | 含义 |
| --- | --- |
| 品红 | **需要你处理**：等你批准、回答，或有对话框等你处理 |
| 红色 | **出错**：因额度用完或 API 出错而停止 |
| 蓝色 | **运行中** |
| 亮绿 | **已完成·未查看**：已完成，你还没看过 |
| 暗绿 | **已完成**：已完成且已查看 |
| 灰色 | **空闲**：被打断、已停止，或最近没有活动 |

灯的形状也不一样（实心或空心），所以不完全依赖颜色区分。浅色主题和高对比度主题会用各自的配色，你也可以在 `workbench.colorCustomizations` 里修改每一种颜色。

对于能上报实时状态的 Claude Code 版本（见 [它读什么](#它读什么)）和 GitHub Copilot Chat，"需要你处理"是确定的，不过 Copilot Chat 最多会晚大约一分钟才显示。对于更早的 Claude Code 版本和 Codex，扩展只能推测。当一个快工具（读、写或编辑文件、搜索、打补丁）连续 60 秒没有结果时，聊天窗口会显示 **可能在等你批准**。Shell 命令等长命令永远不会被推测。你可以用 `agentMonitor.approvalGuess` 修改或关闭这个推测。

### 转到聊天窗口运行的地方

点击聊天窗口标题区里的 **转到**，或者双击列表里的聊天窗口或它的某个智能体，智能体监视器就会调出这个聊天窗口正在运行的地方。单击仍然只是选中聊天窗口或显示智能体详情。**转到对话** 也在聊天窗口的右键菜单和 **…** 菜单里、侧边栏总览的右键菜单里（聊天窗口那一行还有一个行内按钮），以及命令面板里。

| 聊天窗口在哪里运行 | 会发生什么 |
| --- | --- |
| Claude Code 扩展 | 在 Claude Code 里打开这个聊天，按你的 `claudeCode.preferredLocation` 设置放在标签页或侧边栏。这个设置不会被改动 |
| Codex 扩展 | 在编辑器标签页里打开这个对话 |
| GitHub Copilot Chat | 在这个聊天所属工作区的窗口里，用编辑器标签页打开它 |
| VS Code 集成终端里的 Claude Code 或 Codex | 显示那个终端 |
| 另一个 VS Code 窗口 | 由那个窗口打开这个聊天或显示那个终端，并切到最前面。这需要打开 `agentMonitor.shareScanAcrossWindows`（默认打开）。如果那个窗口没能切到最前面，会有消息告诉你该切到哪个窗口 |
| macOS 上的 Terminal.app 或 iTerm2 | 这个应用切到最前面，并选中这个聊天所在的标签页（见下文） |
| Claude 或 Codex 桌面应用，或其他终端应用（Warp、Ghostty、WezTerm、kitty、Alacritty、Windows Terminal 等） | 暂不支持，会有消息说明 |

- **Terminal.app 和 iTerm2：** 第一次使用时，智能体监视器会先问你要不要切换到那个应用里这个聊天的标签页。选择 **继续** 之后，macOS 会询问是否允许 VS Code（或你用的编辑器）控制那个应用，请选择"允许"。每个应用只问一次。如果当时没有允许，下次再试时会弹出带 **打开自动化设置** 按钮的消息；在"系统设置 > 隐私与安全性 > 自动化"里允许后再试一次。以后也可以在那里更改。
- **Codex CLI：** 这类聊天没有可用的进程 ID，所以智能体监视器会在这个聊天的文件夹里找正在运行的 `codex` 进程（如果能看出是哪个进程打开着这个聊天的记录文件，就用那个）。同一个文件夹里有好几个在运行时，会选最新启动的那个，它可能是另一个聊天。在 Windows 上读不到进程所在的文件夹，所以会直接选最新的那个。
- **转不过去时**，会有消息说明原因：例如这个聊天已经不在运行了，它在 VS Code 之外的终端里运行，它是由其他工具或智能体启动的（不在终端或对话面板里），或者没有打开这个 Copilot 聊天所属工作区的 VS Code 窗口。
- **转到按钮**（以及总览里的行内按钮）只在大概率能转过去时出现：还开着的 Claude Code 聊天，以及打开中或 24 小时内有过活动的 Codex 和 Copilot Chat 聊天。双击和菜单总会尝试。
- **只在你要求时才查看。** 只有在你使用转到时，智能体监视器才会列出正在运行的进程：macOS 和 Linux 上调用一次 `ps`，Windows 上调用一次 PowerShell；对 Codex CLI 还会查看这些进程的工作文件夹，以及是哪个进程打开着这个聊天的记录文件（macOS 用 `lsof`，Linux 用 `/proc`）。这些都不会读取你的聊天内容，也不会发送到任何地方。其他 VS Code 窗口通过[它读什么](#它读什么)里说的共用文件夹联系。

### "需要你处理"通知

- 当一个聊天窗口或其中的智能体开始等你（批准、回答或对话框，也包括推测出的 **可能在等你批准**）时，智能体监视器会通知你。如果有 VS Code 窗口在前台，它会在那个窗口里弹出一条消息，带一个 **查看** 按钮：点它会在面板里选中这个聊天窗口。如果当前范围里看不到它，它会暂时加到这个窗口的列表里，直到你选中别的聊天窗口或切换范围；范围设置本身不会改。你正在看的聊天窗口（它的标签页在最前面，或面板正在显示它）不会弹消息。
- 如果所有 VS Code 窗口都不在前台，则改为发系统通知（macOS 和 Linux）。在 Windows 和远程窗口（SSH、WSL、容器）中，消息会在你接下来切换到的 VS Code 窗口里显示，前提是这个聊天窗口还在等。
- 不管开了几个窗口，每次等待只通知一次，由一个窗口负责；装了这个扩展的不同编辑器（VS Code、VS Code Insiders、Cursor 等）之间也是如此。窗口打开时就已经在等的聊天窗口不会通知，只是因为你改了设置才出现的聊天窗口（比如打开了 Codex）也不会通知；不在这个窗口范围里的聊天窗口也会通知。
- 用 `agentMonitor.notifyNeedsYou` 可以关闭通知。所有 VS Code 窗口都不在前台时，记录改为每 5 秒读一次，而不是每 2 秒（`agentMonitor.backgroundRefreshSeconds`）。发系统通知之前还会再读一次记录，这样你已经回答过的提示就不会再通知。所以通知可能要过几秒才到。
- 如果你没及时处理时还想在手机上收到消息，见[推送到手机或团队聊天](#推送到手机或团队聊天)。想同时听到提示音，见[提示音](#提示音)；不想夜里被打扰，见[勿扰时段](#勿扰时段)。

### 推送到手机或团队聊天

可选功能，**默认关闭**。开启后，遇到下面这些情况，智能体监视器可以向你的手机或团队聊天发一条简短消息：

- **智能体需要你**，并且过了 `agentMonitor.push.delaySeconds`（默认 30 秒）还在等。会先弹出桌面通知；你及时处理了就不推送。如果等待期间电脑进入睡眠，醒来后不会再推送这次等待。
- **智能体因 API 错误停止**（立即推送）。
- **Claude Code 或 Codex 的使用额度用完**，以及**额度重置**时。
- **收到阈值提醒**：用量、今天的费用或某个聊天的上下文超过了你设定的值（见[阈值提醒](#阈值提醒)）。对应的事件是 `usageHigh`、`costDaily` 和 `contextHigh`。

这些默认都开启（费用和上下文提醒要等你设了阈值才会出现）。可以在设置菜单的 **选择推送事件…** 里或用 `agentMonitor.push.events` 选择。[勿扰时段](#勿扰时段)内不推送；如果你允许出错照常提醒，API 出错和撞上额度仍会推送。

**联网：** 推送是唯一会联网的功能，所以还需要打开 **允许联网**（`agentMonitor.network.allow`，默认关闭）。它关闭时什么都不会发出，连测试消息也不会，设置菜单里推送会显示为 **已暂停**。如果在它关闭时添加渠道、开启推送或发送测试消息，会先弹出一个对话框，说明会发送什么、发到哪里；只有点它的 **允许联网** 按钮才会打开。用 **禁止联网**（设置菜单、面板的 **…** 菜单或命令面板）可以再关掉：推送仍保持开启，重新允许联网后，中间发生的事情不会补发。允许联网只对这台电脑有效：设置同步不会把它带到你的其它电脑上。

**发送什么：** 项目文件夹名和状态，比如"智能体需要你 · my-app"；额度相关的消息则是产品名和重置时间；阈值提醒则说明超过了什么：用量周期及其百分比、今天的费用超出了预算（不带任何金额），或聊天窗口的上下文百分比。开启 `agentMonitor.push.includeTitle` 后会加上对话标题（以及子智能体名称），但只限真正的标题：你自己设置的，或智能体、应用生成的。由你第一条提示词截取的标题永远不会发送。扩展不会附加提示词、代码、文件路径、token 数或费用；标题和子智能体名称按原样发送，里面可能带有文件名。

**设置方法：** 从命令面板或面板标题栏的 **…** 菜单运行 **智能体监视器：推送通知…**，选择 **添加推送渠道**。选一个服务，阅读隐私说明（每个服务只显示一次），填写各项，再发一条测试消息。令牌、密钥和 Webhook 地址保存在 VS Code 的安全存储里，绝不会写进 `settings.json`。编辑渠道时，密钥类字段留空就会保留已保存的值；可选的密钥（ntfy 访问令牌、飞书或钉钉的签名密钥）输入 `-` 即可删除。密钥不会在电脑之间同步：开启设置同步后，在另一台电脑上添加的渠道会显示 **这台电脑上还没设置**，需要在这台电脑上再设置一次；删除渠道时，只会删掉当前这台电脑上的密钥（留在其他电脑上的那份不会再被使用）。自建的 ntfy 或 Bark 服务器只有本机和内网地址才能用 `http://`。它不加密，而且换到别的网络（咖啡馆、酒店）时，同一个地址可能是别人的设备，所以只在你自己管理的网络里使用。同一个菜单会显示推送是否开启、有几个渠道在用、是否允许联网，还能发送测试消息、编辑、关闭或删除渠道、开关推送、选择事件，以及允许或禁止联网。

| 服务 | 需要准备什么 |
| --- | --- |
| **ntfy** | 安装 ntfy 应用，订阅设置时建议的主题。主题是随机生成的，因为在 ntfy.sh 上任何知道主题的人都能读到它。也可以用自己的服务器和访问令牌。 |
| **Bark**（iPhone） | Bark 应用里的设备密钥：示例网址里紧跟在服务器地址后面的那一段。 |
| **Server酱**（微信） | 在 sct.ftqq.com 获取的 SendKey（`SCT…`，Server酱³ 是 `sctp…`）。免费版每天只能发 5 条，所以这个渠道的每日上限默认是 5。 |
| **飞书 / Lark** | 在群里添加自定义机器人，复制它的 Webhook 地址。开启了签名校验就填上密钥；设置了自定义关键词就填其中一个。 |
| **钉钉** | 在群里添加自定义机器人，复制它的 Webhook 地址。安全设置用"加签"时填上密钥（以 `SEC` 开头），用"自定义关键词"时填其中一个。 |
| **企业微信** | 添加群机器人，复制它的 Webhook 地址。 |
| **Telegram** | 用 @BotFather 创建机器人，粘贴它的令牌和你的 Chat ID。先给机器人发一条消息，因为机器人不能主动发起聊天。 |
| **Discord** | 在频道设置的"整合 > Webhook"里新建一个 Webhook，复制它的网址。 |
| **Slack** | 为频道创建一个传入 Webhook，复制它的网址。 |

**上限：** 几秒内接连发生的动态会合并成一条消息。每个渠道最多每 10 秒一条、每小时 20 条；设置了 **每日上限**（0 表示不限）的话也会遵守。超出每小时或每日上限的消息直接跳过，不会稍后补发，智能体监视器的输出面板里会记下来。上限在所有窗口之间共同计算，每个事件只由一个窗口发送。某个渠道连续失败三次时，会弹出一条带 **打开推送设置** 按钮的警告；在发往这个渠道的消息再次成功之前不会重复提醒。

**远程窗口：** 推送从运行扩展的那台机器发出。在远程窗口（SSH、WSL、容器）里就是远程机器，它需要能访问对应的服务。渠道的密钥也会在那台机器上使用（VS Code 会把它们交给那里的扩展），所以推送开启时，只在你信任的机器上打开远程窗口，或者先关闭推送。

**代理：** 推送经由 VS Code 发出，所以只要 VS Code 把代理设置交给扩展使用（`http.fetchAdditionalSupport`，新版本默认开启），你在 VS Code 里设置的代理（`http.proxy`）就会生效。在代理环境下推送失败时，请检查这些设置。

### 提示音

可选功能，**默认关闭**。打开 `agentMonitor.sound.enabled` 后，遇到下面这些情况，智能体监视器会响一声：

- **智能体需要你**（`agentMonitor.sound.needsYou`）；
- **智能体出错停止**，比如 API 出错或撞上额度（`agentMonitor.sound.error`）；
- **聊天窗口已完成，而你还没看**，也就是灯变成亮绿色的 **已完成·未查看**（`agentMonitor.sound.done`）；
- **收到阈值提醒**（`agentMonitor.sound.alert`，见[阈值提醒](#阈值提醒)）。

每一项都可以设为 `default`、`off`，或 Glass、Ping、Pop、Tink、Submarine、Funk、Hero、Basso 中的一个。`default` 会给每种情况配不同的声音：需要你处理是 Glass，出错是 Basso，完成是 Hero，阈值提醒是 Funk。这些名字是 macOS 的系统提示音，用 `afplay` 播放。在 Linux 上改为播放系统声音主题里相近的声音，通过 `canberra-gtk-play` 或 `paplay`（需要装了其中一个）；在 Windows 上则播放 Windows `Media` 文件夹里相近的声音。"需要你处理"的声音和["需要你处理"通知](#需要你处理通知)一起响，所以还需要打开 `agentMonitor.notifyNeedsYou`。你正在看的那个聊天窗口不会响"需要你处理"和"完成"的声音；"完成"只是推测时也不会响"完成"的声音。每个声音只由一个 VS Code 窗口播放；好几件事同时发生时只响一声：所有窗口加起来最多每 3 秒一声。远程窗口（SSH、WSL、容器）里和[勿扰时段](#勿扰时段)内都不会有声音。

### 勿扰时段

可选功能，**默认关闭**。打开 `agentMonitor.quietHours.enabled` 后，在设定的时段里：

- 不响提示音；
- 不发系统通知，消息会等到你接下来切换到的 VS Code 窗口里再显示；
- 不推送到手机或团队聊天，勿扰时段里发生的事之后也不会补发。

前台 VS Code 窗口里的消息照常弹出，面板、状态灯、角标和状态栏也照常更新。勿扰时段生效期间，状态栏的提示会注明。

- `agentMonitor.quietHours.start` 和 `agentMonitor.quietHours.end` 是本地时间，24 小时制 `HH:MM`，默认 22:00 和 08:00。结束时间早于开始时间时，勿扰时段会跨过午夜。两者相同时，勿扰时段不会生效。
- `agentMonitor.quietHours.days` 可以让它只在某几天生效：`sun`、`mon`、`tue`、`wed`、`thu`、`fri`、`sat`；留空（默认）表示每天。以开始的那天为准：设成 `["fri"]` 时，周五 22:00 到周六 08:00 是勿扰时段。
- 打开 `agentMonitor.quietHours.allowErrors` 后，API 出错和撞上额度时仍会响出错的提示音，也仍会推送。额度重置和阈值提醒照样保持安静。

### 阈值提醒

某个数字超过你设定的值时，智能体监视器也可以提醒你。提醒方式和"需要你处理"通知一样（有 VS Code 窗口在前台时在窗口里弹出消息，否则发系统通知）；开启提示音时会响阈值提醒的声音，开启推送时还会推送。

| 设置项 | 默认值 | 什么时候提醒 |
| --- | --- | --- |
| `agentMonitor.alerts.usagePercent` | `90` | Codex 的 5 小时或每周用量达到这个百分比。只支持 Codex：Claude Code 的本地日志只记录撞上额度，不记录百分比 |
| `agentMonitor.alerts.dailyCost` | `0`（关闭） | 今天的估算等价 API 费用（Claude Code 和 Codex 合计）达到这么多美元 |
| `agentMonitor.alerts.contextPercent` | `0`（关闭） | 某个聊天窗口的主对话达到自动压缩点的这个百分比（Claude Code 和 Codex；GitHub Copilot Chat 没有自动压缩点） |

- 每种提醒只来一次：用量在每个额度周期里一次（重置前不再提醒），费用每天一次，上下文每个聊天窗口在下次压缩前一次。设成 0 就关闭对应的提醒。
- 窗口打开时、或者你修改设置时已经超过阈值的，不会提醒。
- 每条提醒只由一个窗口显示。
- 费用是按官网价目表估算的（见[用量与费用](#用量与费用)），"今天"按你电脑的本地时间算。
- 开启推送时，这些提醒也会推送（见[推送到手机或团队聊天](#推送到手机或团队聊天)）。费用提醒的推送只说今天的费用超出了预算，不带任何金额。

### 顺序不会跳动

- 聊天窗口按开始时间排序，最新的在最上面。智能体按开始时间排序，最早的在最上面。
- 不会因为活动、状态或 token 数而重新排序。智能体完成后，它还留在原地，只有灯的颜色会变。
- 只有当聊天窗口在**打开中**和**最近**之间切换时，它才会移动位置。智能体表格是原地更新行的，所以滚动位置和展开的行都会保持不变。

### 压缩按钮：可选模型，带费用估算

![为一个已关闭的 Claude Code 会话选择压缩方式，每个模型都有估价](../images/compact.png)

上下文达到 20K token 以上的每个 Claude Code 或 Codex 聊天窗口都会出现一个 **压缩…** 按钮，聊天窗口列表里悬停时的那一行上，以及它标题区（智能体上方）里都有。点击之前什么都不会执行。

- **Claude Code 聊天窗口是打开的：** 扩展会切换到那个聊天窗口，把 `/compact` 填进它的输入框，后面跟着一段模板，说明摘要必须保留什么（目标、决定、未解决的问题、文件路径、你说过的约束）。这段文字也会同时复制到剪贴板。你可以先编辑一下，再自己按回车。
- **Claude Code 聊天窗口是关闭的：** 扩展可以用你本机的 Claude Code 在后台压缩它，并让你选模型：
  - 该聊天窗口原来用的模型；
  - Claude Sonnet 5；
  - Claude Haiku 4.5，仅当上下文能放进它的 200K 窗口时可选。

  每个选项都会显示预计费用，最便宜的会标为 **推荐**。执行前会先弹一个确认对话框（可以关闭）。真正运行之前，扩展会再检查一次，如果聊天窗口已经被重新打开就会停止。
- **估价会考虑提示缓存的状态。**
  - 缓存还没过期时，用原来的模型压缩最便宜。
  - 缓存过期之后，换一个更便宜的模型大约能省一半。
  - 例如，一个 Claude Opus 5.5 会话有 400K token 的上下文：缓存还在时约 $0.40；1 小时缓存过期后，用原模型约 $3.52，换 Sonnet 5 约 $1.76。
- **菜单里还有：** **写一份交接笔记**，适合你要切换到新任务的时候。对于新任务，开新会话比压缩更合适。
- **提醒**（每一项都可以关闭）：
  - 在大型空闲聊天窗口的提示缓存即将过期前，或者你关闭一个大型聊天窗口时，趁压缩还便宜提醒你；
  - 压缩之后，提醒你检查关键规则是否还在。
- **Codex 聊天窗口：** 扩展会在 Codex 中打开该对话，并复制好 `/compact` 供你粘贴。
- **压缩次数：** **详情** 里显示 **已压缩 N 次**（自动 + 手动）。压缩两次或以上后，如果上下文又变大了，会建议写交接笔记并重新开始。当一个聊天窗口在 10 分钟内压缩了两次，或者压缩后立刻又进入"建议尽快处理"区间时，会用出错的颜色显示 **可能陷入压缩循环**。"两次"是经验值，不是精确测量的上限。

### 自己设置自动压缩容量

Claude Code 会在上下文到达某个容量时自动压缩，这发生在你还在工作的时候，缓存是热的，压缩本身也便宜。你能选的是*容量设多少*。点击聊天窗口 **详情** 里的 **自动压缩：… ▾**，或者右键点击一个聊天窗口，选择 **设置自动压缩阈值…**。

- 列表会把每个预设档位换算成这个聊天窗口对应模型的容量（百分比和 token 数）、大约会在哪里实际压缩、依据有多强，并给出类似"每次调用约 $0.069，比默认省 45%"这样的估算。**自定义…** 接受 100K 到 1M 之间的任意值，**查看参考说明** 会打开这些数字背后的说明文档。
- **所有项目：** 如果聊天窗口是打开的，扩展会在这个聊天窗口里预填 `/autocompact <值>`；按回车后 Claude Code 会立刻应用，并保存到你的用户设置。如果聊天窗口是关闭的，扩展会把 `autoCompactWindow` 写进 `~/.claude/settings.json`。
- **仅这个项目：** 扩展会把 `autoCompactWindow` 写进 `<项目>/.claude/settings.local.json`，它的优先级高于用户设置。新开的会话会用这个值；已经打开的会话可能需要重新打开。
- 扩展写设置文件时只会改这一个键，保留你原有的格式，写之前先备份，如果文件解析不了就完全不写。选择 **保持默认** 会删掉这个键。
- **Codex：** 扩展不会修改 `config.toml`。它会复制一行，比如 `model_auto_compact_token_limit = 217600`，打开 `~/.codex/config.toml`，并请你把它粘贴到文件开头、任何 `[表]` 之前。

没有任何厂商或论文给过"调研用 X%、写代码用 Y%"这样的标准答案。下面这些档位是在厂商默认值、厂商评测配置、从业者数据和成本模型之间的折中，依据一栏标出了每一档有多可靠。

| 档位 | 1M 窗口模型：设定值 → 约在这里压缩 | 200K 窗口模型 | Codex | 每次调用（Opus 5.5，1M）/ 相对默认 | 依据 |
| --- | --- | --- | --- | --- | --- |
| **保持默认**（给不想操心的人） | 不设 → 约 967K | 不设 → 约 167K | 90%（约 245K） | $0.126 / 100% | 强：厂商默认值，官方强烈推荐 |
| **写代码（均衡）** | 400K（40%）→ 约 367K | 不设 | 90% | $0.069 / 约 55% | 中：一位从业者对 873 次压缩的观察数据（构建/理解代码约 300–450K）加从业者经验，没有对照实验 |
| **调研 / 检索** | 250K（25%）→ 约 217K | 160K（80%）→ 约 127K | 80% | $0.056 / 约 44% | 中：Anthropic 自家的搜索评测配置在 200K 触发；DeepSeek-V3.2、Kimi K2.5 在窗口 80% 触发。风险：更容易丢掉最初的问题，建议写进文件 |
| **长时间自主运行** | 600K（60%）→ 约 567K | 不设 | 90% | $0.088 / 约 70% | 弱：折中方案，没有直接证据；最重要的是把目标和约束写进文件 |
| **省钱优先** | 200K（20%）→ 约 167K | 不设（调低也不省钱） | 80% | $0.052 / 约 41% | 中：成本模型加同一位从业者的成本最优点（约 220K）。代价：压缩次数约为默认的 7 倍，信息损失最多 |

- **设的值不等于实际压缩点。** 实际会提前约 33K 压缩（推算自官方"1M 约在 967K 压缩"），所以"400K"其实约在 367K 压缩。
- **在 200K 窗口的模型上，调低阈值几乎不省钱**（每次约省 3%），所以只在看重质量时才这样做。设定值不能低于 100K，所以这些模型只能用 50%–100%。
- **同一个值适用于所有模型。** 如果你在同一个作用范围里切换 1M 和 200K 模型，较小的窗口会把它封顶。
- **每次压缩都会丢细节。** 长期规则写进 `CLAUDE.md`，换任务时开新会话，而不是压缩。
- **成本模型：** 缓存一直是热的；每次调用新增约 3K token；压缩后剩约 30K；摘要约为压缩点的 4%（2K–20K）。价格按该聊天窗口的模型计算。
- **Claude Code 自己的建议：**"The auto setting picks a window tuned for your model and is strongly recommended for the best cost and performance. Overriding auto may result in high token usage, especially when resuming long sessions."（auto 设置会为你的模型选一个调好的容量，为了最好的成本和性能，强烈推荐使用它；覆盖 auto 可能导致 token 用量偏高，尤其是续接长会话时。）它没有说明原因。可能的原因：续接一个已经比新阈值还大的旧聊天窗口时会立刻压缩，而且缓存是冷的；阈值离聊天窗口一开始的大小太近，会反复压缩；摘要里丢的细节可能导致额外调用去重新读文件。
- 如果给 Claude Code 设置了 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`，它会覆盖以上所有设置。

完整的参考说明，附带出处（其它工具的默认值、厂商评测、博客建议和成本模型），见 [docs/compaction-threshold-guide.zh-CN.md](compaction-threshold-guide.zh-CN.md)（中文）。

点击一个智能体可以看到它最近的步骤、最终结果（带复制按钮）、它改过的文件（点击可以打开）和它的工具报错。**打开记录文件** 会打开原始的会话记录。

### 用量与费用

- **上下文：** 相对自动压缩点用了多少（例如"412K / 967K 自动压缩"）、占模型窗口的百分比（"占 1M 窗口的 41%"），以及距自动压缩还剩多少。进度条会随着聊天窗口接近自动压缩而填满。
- **百分比和窗口都直接用 Claude Code 和 Codex 自己的数。** 百分比用 Claude Code 自己的公式：上下文 token 数（最近一次调用的输入 + 缓存写入 + 缓存读取）÷ 上下文窗口，四舍五入。窗口来自 Claude Code 这次会话的费用记录（能看出模型是不是用 1M 窗口跑的），否则用模型的标准窗口；Codex 则来自 Codex 的日志。其他工具见[支持的工具](#支持的工具)。
- **自动压缩发生在哪里、为什么：** 依次来自你的设置（这个项目的本地设置、这个项目的设置，或者你的用户设置），否则是**实测**（记住这个模型上次在哪里自动压缩，由扩展记住），否则是官方默认值。提示会说明用的是哪一种。如果给 Claude Code 设置了 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`，它会比显示的更早压缩；扩展看不到 Claude Code 的环境变量。
- **上下文提示：** 当上下文较大、值得在下一个合适的节点处理时，会出现柔和的提示标签（"可以考虑压缩"、"建议尽快处理"）。它们从不改变灯的颜色。
- **提示缓存：** 每个 Claude Code 聊天窗口的缓存倒计时（"缓存：还剩 38 分钟"）。
- **等价 API 费用：** 每个智能体、每个聊天窗口，以及今日的总计（仅 Claude Code 和 Codex）。对于 Claude Code 聊天窗口，标题栏显示的是 Claude Code 自己的累计费用（"Claude Code 的统计"）；其余的都是按 token 数与官网价目表估算出来的。订阅套餐不是这样计费的，所以只作比较参考。GitHub Copilot Chat 显示的是 Copilot credits，而不是费用（见[支持的工具](#支持的工具)）。

- 显示 Claude Code 聊天窗口何时撞上会话、每周或模型额度，以及额度何时重置。
- 显示 Codex 的 5 小时和每周用量百分比。

### 聊天窗口存在哪里，以及怎么搬走

提示缓存存放在 Anthropic 和 OpenAI 的服务器上，不占用你电脑的空间。真正占空间、并被反复写入的是聊天记录、文件备份、插件和日志。在一台测试机器上，每个 Claude Code 会话进程每小时写盘 23–78 MB、读盘 14–36 MB，占用 300–400 MB 内存；`~/.claude/projects` 有 932 MB，`~/.codex` 里插件占 298 MB、会话占 52 MB。

这么多写入量对 SSD 寿命影响不大。真正的问题是系统盘的剩余空间。搬走这些文件能腾出空间，但不会减少内存占用。

**智能体监视器：存储位置与占用**（在面板标题栏的 **…** 菜单里，或命令面板里）会显示：

- Claude Code 的数据文件夹（`CLAUDE_CONFIG_DIR` 或 `~/.claude`），以及 `projects`、`file-history`、`plugins`、`skills`、`cache`、`backups`、`shell-snapshots` 和 `~/.claude.json` 各有多大；
- Codex 的文件夹（`CODEX_HOME` 或 `~/.codex`），它的子文件夹和数据库文件；
- 哪些项已经是软链接，以及它们指向哪里；
- 每块磁盘的剩余空间；
- Claude Code 保留记录多久（`cleanupPeriodDays`，不改的话是 30 天）。

这个页面只覆盖 Claude Code 和 Codex。大小统计在后台进行，只在页面打开时才算，最多每 10 分钟一次。

> **迁移方案仅供参考。** 这些方案是按你电脑上的路径自动生成的，不是经过验证的操作流程。请自己逐条核对路径和命令，先备份重要数据，是否运行由你自己决定，运行的后果（包括数据丢失）由你自己承担。本扩展按“原样”提供，不附带任何担保。在页面上，要先勾选确认，才能复制命令或把命令放进终端。

它还会准备好把数据搬到别的文件夹的命令。默认建议是剩余空间最多的非系统盘，你也可以自己选文件夹。

- **方案 A（推荐）：只搬最大的那个文件夹，留一个软链接。** 对 Claude Code 是 `projects`，对 Codex 是 `sessions`。在 macOS 和 Linux 上，命令大致是这样（实际生成的命令还会先检查有没有障碍）：

  ```sh
  mkdir -p '/Volumes/External/AI-Data/claude/projects' \
    && rsync -a ~/.claude/projects/ '/Volumes/External/AI-Data/claude/projects/' \
    && mv ~/.claude/projects ~/.claude/projects.bak \
    && ln -s '/Volumes/External/AI-Data/claude/projects' ~/.claude/projects
  # 确认一切正常后再删除备份：rm -rf ~/.claude/projects.bak
  ```

  在 Windows 上用的是 `robocopy` 加目录联接（`mklink /J`）。这些 Windows 命令还没有在 Windows 上实际跑过。
- **方案 B（官方）：用 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME` 搬整个文件夹。** 在 VS Code 里，通过 Claude Code 扩展的 `claudeCode.environmentVariables` 设置来设置；在终端里则加进你的 shell 配置。换目录后可能需要重新登录（未验证）。

开始搬动前：

- 页面会列出还打开着的聊天窗口。请先关掉它们，搬动期间也不要开新的。
- 外置磁盘必须在启动 Claude Code 或 Codex 之前就接好，不然链接会指向不存在的地方，会话会保存失败，或者在一个空文件夹里重新开始。
- 不要用 iCloud 云盘或 Dropbox 这类同步文件夹；持续写入会和同步冲突。
- 在确认一切正常之前，保留 `.bak` 备份。

**扩展绝不会自己执行这些命令。** **复制命令** 只是复制它们，**在终端中打开** 会把它们打进一个新终端、不按回车，方便你自己检查后再运行。扩展会跟着数据走到哪里：软链接对它是透明的，`CLAUDE_CONFIG_DIR` 和 `CODEX_HOME` 也会被遵守。如果你完全不想保存某个聊天窗口，Claude Code 的 `--no-session-persistence` 参数可以关掉记录（这样智能体监视器就看不到那个聊天窗口了）。

### 支持的工具

- **Claude Code**：VS Code 扩展、终端或桌面应用里的，包括子智能体、后台智能体和工作流。
- **Codex**：VS Code 扩展、CLI 或桌面应用里的，包括子智能体和审阅线程。
- **GitHub Copilot Chat**：VS Code 内置的聊天，包括智能体模式和它的子智能体。
- 没安装的工具会直接跳过；每个工具都可以在设置里单独关闭（见[设置](#设置)）。

各工具记录的内容不同，扩展能看到的也不同：

| | GitHub Copilot Chat |
| --- | --- |
| **打开中、运行中、已完成** | 从聊天记录里读出，但最多晚大约一分钟：VS Code 大约每分钟才保存一次聊天 |
| **需要你处理** | 确定，同样有这个延迟 |
| **Token 与费用** | 整个聊天的 token（不分子智能体），显示 Copilot credits 而不是美元费用 |
| **上下文** | 窗口来自 VS Code 随聊天保存的模型信息。没有自动压缩点 |

用量历史、今日总费用（以及对应的提醒）和[存储页面](#聊天窗口存在哪里以及怎么搬走)只覆盖 Claude Code 和 Codex。**压缩…**、交接笔记、自动压缩阈值和续跑提示也只对 Claude Code 和 Codex 的聊天窗口提供；后台压缩仍然只支持 Claude Code。

### 终端版

![终端版用同样的灯和同样固定不变的顺序](../images/terminal.png)

同一套监视逻辑也能在终端里跑。它包含在源码仓库里，不在扩展包里，需要 Node.js 20 或更高版本（在 Node.js 20、22 和 24 上测试过）：

```sh
git clone https://github.com/cyuneo/cyuneo-agent-monitor.git
cd cyuneo-agent-monitor
node bin/agent-monitor.js --watch          # 原地刷新；按 q 或 Ctrl+C 退出
node bin/agent-monitor.js --session 1a2b   # 详细显示一个聊天窗口：步骤、结果、文件、报错、续跑
node bin/agent-monitor.js --json           # 以 JSON 形式输出数据
```

其它选项还有 `--provider all|claude|codex|copilot`（默认 `all`）、`--window <minutes>`、`--here`（只显示当前文件夹里的聊天窗口）、`--today`、`--lang en|zh-cn|zh-tw|ko|ja` 和 `--no-color`。运行 `--help` 查看完整列表。

## 它读什么

一切都是只读的，只有一个例外由你自己触发：当你设置自动压缩阈值时，扩展可能会把 `autoCompactWindow` 这个键写进 Claude Code 的某个设置文件（见[自己设置自动压缩容量](#自己设置自动压缩容量)）。当你在后台压缩一个已关闭的聊天窗口时，是 Claude Code 自己把摘要写进那个聊天窗口的记录里的。

| 文件 | 用途 |
| --- | --- |
| `~/.claude/projects/<project>/<session>.jsonl` | Claude Code 聊天窗口（主对话） |
| `~/.claude/projects/<project>/<session>/subagents/…` | 子智能体、后台智能体和工作流智能体 |
| `~/.claude/projects/<project>/<session>/workflows/…` | 工作流名称、状态和结果 |
| `~/.claude/sessions/*.json` | Claude Code 自己维护的运行中会话列表：哪些聊天窗口是打开的，每一个是否正在忙碌，或者在等批准、回答或对话框。只读取 `.json` 文件，旁边的 `.key` 文件和 socket 一律不打开。 |
| `~/.claude/settings.json`、`<项目>/.claude/settings.json`、`<项目>/.claude/settings.local.json` | 你的自动压缩设置（`autoCompactWindow`、`autoCompactEnabled`）和 `cleanupPeriodDays` |
| `~/.claude/file-history/<session>` 以及 `~/.claude`、`~/.codex` 下的其它文件夹 | 只统计大小（用于记录文件那一行和存储页面），不会打开文件内容。 |
| `~/.codex/sessions/**/rollout-*.jsonl` | Codex 线程，包括子智能体和审阅线程以及用量额度 |
| `~/.codex/session_index.jsonl` | Codex 线程标题 |
| `~/.codex/models_cache.json`、`~/.codex/config.toml` | Codex 上下文窗口和自动压缩阈值 |
| `<User>/workspaceStorage/<workspace>/chatSessions/<session>.jsonl`（或 `.json`） | 打开了文件夹或工作区的窗口里的 GitHub Copilot Chat 聊天。`<User>` 是你正在用的 VS Code 的 User 文件夹，例如 macOS 上的 `~/Library/Application Support/Code/User`、Linux 上的 `~/.config/Code/User`、Windows 上的 `%APPDATA%\Code\User` |
| `<User>/globalStorage/emptyWindowChatSessions/<session>.jsonl`，以及 `<User>/profiles/<profile>/` 下的同一位置 | 没打开文件夹的窗口里的 Copilot Chat 聊天，包括其他配置文件（profile）里的 |
| `<User>/workspaceStorage/<workspace>/workspace.json` | Copilot Chat 聊天属于哪个文件夹 |

上面列的是默认路径。`CLAUDE_CONFIG_DIR` 和 `CODEX_HOME` 都会被遵守。你也可以用 `agentMonitor.claude.projectsDir` 和 `agentMonitor.codex.home` 指向别的位置。

对 GitHub Copilot Chat 的文件，扩展只读，从不写入它们，也不往这个工具的文件夹里写任何东西。它们的内容不会发到任何地方；只有打开推送后，才会发出[推送到手机或团队聊天](#推送到手机或团队聊天)里说的那种简短消息。

扩展在 VS Code 自己的存储里保留一些很小的东西：哪些聊天窗口你已经看过、哪些提醒你关掉了、每个模型实测的自动压缩点，以及它改过的设置文件的备份。只有在你点击复制或压缩相关操作时，它才会写入剪贴板。

只要 `agentMonitor.shareScanAcrossWindows` 是打开的（默认如此），即使只开了一个窗口，各窗口也会在扩展的全局存储里共用一个文件夹（`shared-scan`）。里面记着由哪个窗口读取记录，这个窗口还会把最新结果存到 `shared-scan/snapshot.json` 给其他窗口用：聊天标题、项目文件夹、步骤和费用。结果一变这个文件就会被覆盖，这个窗口正常关闭时会删除它。每个窗口还会在这里留一份自己的小记录，写着它的文件夹以及扩展宿主和各个终端的进程 ID，这样[转到](#转到聊天窗口运行的地方)才能找到聊天在哪个窗口里运行；请另一个窗口打开某个聊天的请求也是这里的一个小文件，那个窗口接手时就会删除它。通知方面，每次等待会在系统临时目录下的一个私有文件夹里留一个小标记（只有哈希值，没有聊天内容），确保在所有编辑器里只有一个窗口显示这条通知。标记一天后删除。开启推送后，每个推送渠道的发送时间（不含消息内容）也记在同一个文件夹里（`push-sent.json`），这样上限能在各窗口之间共同生效。

[用量历史](#用量历史)页面会在扩展的存储里保留一份缓存：它读过的每个记录文件的路径、大小和读到的位置，每天每个模型的 token 数，以及用来避免重复计数的消息 ID。不保存任何聊天内容。只有页面打开时，这份缓存才会更新。

## 隐私

- **除非你打开允许联网，扩展不发起任何网络请求**（`agentMonitor.network.allow`，默认关闭）。关闭时，代码会拒绝每一个请求，推送通知和测试消息也不例外。目前只有推送通知会用到它。没有遥测、没有分析、没有远程内容。
- **推送通知是可选的，默认关闭。** 开启后，只有一条简短消息会发到你设置的服务：项目文件夹名和状态（你允许的话再加上对话标题和子智能体名称）。其他任何内容都不会离开你的电脑。和任何网络请求一样，服务商会看到这条消息和你的 IP 地址。令牌和 Webhook 地址保存在 VS Code 的安全存储里，在显示或记录的错误信息里都会被遮盖。
- **在后台压缩一个已关闭的聊天窗口要通过 Claude Code**，并且只在你确认之后。这时扩展会运行你本机的 Claude Code（`claude -p --resume <session> --model <model> --output-format json "/compact …"`）。Claude Code 会像你自己使用它时一样连接到 Anthropic，用量会计入你的套餐或 API 账单。
- **压缩一个打开中的聊天窗口，或者设置它的自动压缩阈值，都只是把文字放进它的输入框**（`/compact …` 或 `/autocompact …`）。在你按下回车之前，什么都不会发送。（聊天窗口没打开，或者只对这个项目生效时，阈值改为写进设置文件，见[它读什么](#它读什么)。）
- **搬动数据由你自己决定。** 存储页面只生成命令，扩展绝不会自己执行；**在终端中打开** 也不会替你按回车。
- **转到只在你使用时才查看进程。** 为了找到聊天在哪个终端或窗口里运行，它会列出你电脑上正在运行的进程（见[转到聊天窗口运行的地方](#转到聊天窗口运行的地方)）。这不会读取你的聊天内容，也不会发送到任何地方。只有在你确认之后，它才会控制 Terminal.app 或 iTerm2 去选中标签页，而且 macOS 也会先征求你的许可。
- **参考说明链接** 只有在你点击时，才会在浏览器里打开 GitHub 上的一个页面。
- **桌面通知只在本机显示。** 通知由 VS Code 或系统自带的通知命令显示（macOS 用 `osascript`，Linux 用 `notify-send`），内容是聊天窗口的标题和项目文件夹名。不会通过网络发送任何东西。
- **提示音在本机播放**，用的是系统自带的播放器（macOS 用 `afplay`，Linux 用 `canberra-gtk-play` 或 `paplay`，Windows 用 PowerShell）。不会通过网络发送任何东西。
- **用量历史在本机计算**，缓存在扩展的存储里，不会发送到任何地方。
- **你的对话内容保留在本机。** 聊天标题、步骤和结果只会显示在你自己的 VS Code 里（通知则显示在你自己电脑的通知区域）。
- **这些数字是给你看的，不是给模型看的。** 上下文大小、缓存倒计时和费用永远不会传给模型。

## 上下文与压缩小贴士

这些提示来自对公开研究和官方文档的梳理。完整笔记及出处见 [docs/research-context-compaction.zh-CN.md](research-context-compaction.zh-CN.md)（中文）。关于怎么选自动压缩容量，见 [docs/compaction-threshold-guide.zh-CN.md](compaction-threshold-guide.zh-CN.md)（中文）和[自己设置自动压缩容量](#自己设置自动压缩容量)。

1. **不要为了保险就压缩。** 如果任务进行顺利，1M 上下文的模型还在 200K token 左右以下，就不用管它。低于约 50K 时几乎没什么可省的，压缩只会丢细节。
2. **在节点处压缩，并说明要保留什么。** 好的时机是探索阶段结束，或者一个子功能做完了，而不是任务进行到一半。用 `/compact 请保留：目标、决定及原因、未解决的问题、文件路径，以及"不要推送"之类的约束`。超过约 500K 时，在下一个节点处理，不要等自动压缩在任务中途触发。
3. **把长期规则写进文件。** 用项目根目录的 `CLAUDE.md`（Codex 用 `AGENTS.md`）。只在对话里说过的规则，压缩后常常会丢失。
4. **换任务就开新会话。** 用 `/clear`，需要的话先写一份交接笔记，并且自己先读一遍再放心用。如果走错了方向，用 `/rewind` 而不是压缩。
5. **趁缓存还在时压缩。** 压缩要重新读取整段上下文，缓存还在时这样做很便宜。参见[压缩按钮](#压缩按钮可选模型带费用估算)一节的例子。
6. **留意压缩次数。** 压缩两次或以上后（这是经验值，不是精确的上限），如果还有很多要做，就写一份交接笔记重新开始。每次压缩后，都要检查关键约束——尤其是提交、推送和删除权限——是否还在。
7. **给子智能体开 1 小时缓存前先想清楚。** 每次缓存写入都会贵 60%（2 倍而不是 1.25 倍的输入价格）。只有子智能体经常停顿超过 5 分钟时才划算。撞额度的停顿通常要几个小时，比 1 小时缓存还长。

## 已知局限

- **记录格式可能会变。** 这三个工具的记录格式都是内部格式，任何更新都可能改变它。扩展读不懂的行会被跳过。
- **步骤可能会滞后。** 记录是在每次模型调用后写入的，所以在一段长时间的思考中，显示的步骤是最后写入的那一个。
- **"需要你处理"只有在应用上报状态时才是确定的。** 也就是说，能在 `~/.claude/sessions` 里上报实时状态的 Claude Code 版本，以及 GitHub Copilot Chat。更早的 Claude Code 版本和 Codex 依赖上面说的推测，而且 Codex 几乎不会把等待批准和报错写到磁盘上。
- **GitHub Copilot Chat 最多会晚大约一分钟。** VS Code 大约每分钟才把聊天保存到磁盘一次，所以新的步骤、答完的回复或等你处理的提示，最多会晚一分钟才显示。
- **费用是估算值。** 它们按提示中显示日期的官网价目表计算，价格会变。有些模型，比如 Codex 的审阅模型，没有公开价格。GitHub Copilot Chat 显示的是 Copilot credits，不是费用。
- **有些功能只覆盖 Claude Code 和 Codex。** 用量历史、今日总费用（以及每日费用提醒）和存储页面都不包括 GitHub Copilot Chat；它也没有自动压缩点。**压缩…**、交接笔记、自动压缩阈值和续跑提示也只对 Claude Code 和 Codex 的聊天窗口提供。
- **不显示 Claude Code 的用量百分比。** Claude Code 不会把它保存到本地文件，所以对于 Claude，扩展只能显示额度触发和重置时间，用量阈值提醒也只支持 Codex。
- **标签页跟随有盲区。** 它靠标签标题匹配 Claude Code，靠对话 ID 匹配 Codex。侧边栏视图（而不是编辑器标签页）里显示的聊天窗口无法被检测到。
- **可选模型的后台压缩只支持 Claude Code。** Codex 在自己内部压缩。一个聊天窗口打开时不能在后台压缩。
- **Claude Code 的环境变量对扩展不可见。** `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 和 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 可能让 Claude Code 在跟界面显示不同的地方压缩。只有模型自动压缩过一次之后，才会出现实测值。
- **多个窗口共用一次记录读取。** 开着多个 VS Code 窗口时，由其中一个窗口读取记录，其他窗口显示它的结果，通常只晚一点点。这个窗口关闭时，另一个窗口会立刻接手；如果它失去响应，大约 10 秒内接手（所有 VS Code 窗口都不在前台时会更久，因为这时各窗口只按 `agentMonitor.backgroundRefreshSeconds` 的间隔互相确认）。读取设置不同（文件夹、活跃时间范围、推测方式）或扩展版本不同的窗口会各自读取；共用的文件夹写不进去时（比如磁盘满了），每个窗口也会各自读取。可以用 `agentMonitor.shareScanAcrossWindows` 关闭共用。
- **系统通知比较简单。** 在 macOS 上通知通过 AppleScript 显示，所以会显示在 **脚本编辑器**（Script Editor）名下，允许或静音它们也要到"系统设置 > 通知"里找脚本编辑器。点击通知会打开脚本编辑器，而不是 VS Code：请自己切回 VS Code，在等你的聊天窗口亮着品红色的灯。在 Windows 和远程窗口中暂时没有系统通知，消息会改在你接下来切换到的 VS Code 窗口里显示。在 Linux 上如果没有安装 `notify-send`，会改为显示 VS Code 消息。
- **不能在通知里直接批准或回答。** 智能体监视器只读取记录；要在通知里回复，就得接入 Claude Code 或 Codex 的 hooks，或者远程控制它们。请切到那个聊天窗口里回答。
- **点击系统通知不能直接转到那个聊天。** 系统通知由系统自己显示，没法回调扩展。请改用面板里的 **转到**：在 VS Code 消息里，**查看** 会在面板里选中这个聊天窗口，**转到** 则会带你去它运行的地方，不管它在哪个窗口。
- **转到还不能去所有地方。** Claude 和 Codex 桌面应用里的聊天，以及 Terminal.app 和 iTerm2 以外的终端应用（Warp、Ghostty、WezTerm、kitty、Alacritty、Windows Terminal 等）里的聊天，暂不支持。对于 Codex CLI，同一个文件夹里有好几个在运行时，会选最新启动的那个。只有打开 `agentMonitor.shareScanAcrossWindows` 时，才能转到另一个 VS Code 窗口里的聊天。
- **提示音只在 macOS 上实测过。** 在 Linux 上，它通过 `canberra-gtk-play` 或 `paplay` 播放；在 Windows 上，通过 PowerShell 播放 Windows `Media` 文件夹里的声音。这两个平台都还没有实测过。
- **Windows 的迁移命令还没有在 Windows 上实测过。** 存储位置页面生成的 `robocopy` 和 `mklink /J` 命令只核对过文字。运行前请先看一遍，确认一切正常之前不要删掉 `.bak` 备份文件夹。
- **终端版不推送。** 推送通知只由 VS Code 扩展发送。
- **钉钉加签还没有用真实机器人试过。** 签名按钉钉的文档实现，也只对照文档核对过。如果开启加签的机器人拒收消息，请把它的安全设置改用自定义关键词，并在 [GitHub Issues](https://github.com/cyuneo/cyuneo-agent-monitor/issues) 告诉我们。
