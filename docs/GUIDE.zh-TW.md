## 功能

### 像終端機一樣的面板

- **智慧體監視器**（英文介面為 Agent Monitor）會以一個分頁出現在底部面板，就在終端機旁邊，看起來也和終端機一樣：一個整體面板，沒有額外的檢視標題列。選取聊天視窗的智慧體佔了面板的大部分，一列窄的聊天視窗清單放在一側，就像終端機的分頁清單。
- **聊天視窗清單。** 每一個開啟中和最近的聊天視窗，各帶一個狀態燈。它們分成 **開啟中**（Claude Code 還開著這個聊天，或 Codex 正在一輪對話中）和 **最近**。列高和終端機分頁一樣，選取的聊天視窗會醒目提示。為了給標題留出空間，每一列只有狀態燈和標題；當上下文較大、值得處理時，標題後面會加一個小標記：**◔** 建議考慮壓縮，**◕** 建議盡快處理。把滑鼠停在該列上可以看到狀態、上下文等詳情。
- **清單位於終端機分頁清單所在的那一側**（預設右側，跟隨 `terminal.integrated.tabs.location`）；也可以自行設定 `agentMonitor.sessionListPosition` 放在左邊或右邊。拖動分隔線可以調整寬度，按兩下分隔線恢復到預設的 200px，或把它拖到快關上，收成一條只顯示狀態燈的窄條。面板窄於 500px 時會自動使用窄條。寬度會被記住。
- **把滑鼠停在聊天視窗上**會出現 **壓縮…** 按鈕（上下文達到 20K 或以上）和一個 **…** 按鈕，裡面是和右鍵選單一樣的操作。也可以用鍵盤：方向鍵、Home、End 在清單裡移動，Enter 或空白鍵選取，輸入文字可依首字母跳到某個聊天視窗，Shift+F10 開啟操作選單。
- **智慧體。** 點擊一個聊天視窗，就能看到它裡面正在跑什麼：最上面是主對話，然後是子智慧體和背景智慧體，工作流程智慧體則依工作流程分組顯示。
- **聊天視窗的標題區只佔兩列**，面板矮也能直接看到智慧體。第一列是標題，**壓縮…** 旁邊寫著上下文用了多少（「上下文 41%」）；第二列是狀態、上下文離自動壓縮還有多遠、提示、快取倒數和這個聊天的費用。其餘內容（上下文進度條、自動壓縮設定、今日合計、提示、續跑提示、記錄檔案那一列）收在 **詳細資料 ▸** 裡。遇到額度中斷、API 錯誤、壓縮迴圈這類緊急情況，才會多出一列。智慧體表的表頭在捲動時固定在頂端；面板矮於 400px 時，費用和用時兩欄會隱藏。
- 當你切換到 Claude Code 或 Codex 的聊天分頁時，清單裡會自動選取對應的聊天視窗。這只會在你切換分頁時發生，絕不會在重新整理時發生，所以你的選取不會被打斷。
- 側邊欄裡還有一個 **總覽** 樹狀檢視，狀態列有一個帶計數的狀態燈，還有一個標記顯示有多少聊天視窗需要看一眼。

### 狀態燈

同樣的六種燈在各處保持一致：工作階段清單、智慧體表格、總覽、狀態列和終端機版。

| 顏色 | 意義 |
| --- | --- |
| 洋紅 | **需要你處理**：等你核准、回答，或有對話框等你處理 |
| 紅色 | **錯誤**：因額度用完或 API 錯誤而停止 |
| 藍色 | **執行中** |
| 亮綠 | **已完成·未查看**：已完成，你還沒看過 |
| 暗綠 | **已完成**：已完成且已查看 |
| 灰色 | **閒置**：被中斷、已停止，或最近沒有活動 |

燈的形狀也不一樣（實心或空心），所以不完全依賴顏色區分。淺色主題和高對比度主題會用各自的配色，你也可以在 `workbench.colorCustomizations` 裡修改每一種顏色。

對於能回報即時狀態的 Claude Code 版本（見 [它讀什麼](#它讀什麼)），「需要你處理」是確定的。對於更早的版本和 Codex，擴充功能只能推測。當一個快速工具（讀取、寫入或編輯檔案、搜尋、修補）連續 60 秒沒有結果時，聊天視窗會顯示 **可能在等你核准**。Shell 命令等長時間命令永遠不會被推測。你可以用 `agentMonitor.approvalGuess` 修改或關閉這個推測。

### 順序不會跳動

- 聊天視窗依開始時間排序，最新的在最上面。智慧體依開始時間排序，最早的在最上面。
- 不會因為活動、狀態或 token 數而重新排序。智慧體完成後，它還留在原地，只有燈的顏色會變。
- 只有當聊天視窗在**開啟中**和**最近**之間切換時，它才會移動位置。智慧體表格是原地更新列的，所以捲動位置和展開的列都會保持不變。

### 壓縮按鈕：可選模型，帶費用估算

![為一個已關閉的 Claude Code 工作階段選擇壓縮方式，每個模型都有估價](../images/compact.png)

上下文達到 20K token 以上的每個聊天視窗都會出現一個 **壓縮…** 按鈕，聊天視窗清單裡滑鼠停留時的那一列上，以及它標題區（智慧體上方）裡都有。點擊之前什麼都不會執行。

- **Claude Code 聊天視窗是開啟的：** 擴充功能會切換到那個聊天視窗，把 `/compact` 填進它的輸入框，後面接著一段範本，說明摘要必須保留什麼（目標、決定、未解決的問題、檔案路徑、你說過的約束）。這段文字也會同時複製到剪貼簿。你可以先編輯一下，再自己按 Enter。
- **Claude Code 聊天視窗是關閉的：** 擴充功能可以用你本機的 Claude Code 在背景壓縮它，並讓你選模型：
  - 該聊天視窗原本使用的模型；
  - Claude Sonnet 5；
  - Claude Haiku 4.5，僅當上下文能放進它的 200K 視窗時可選。

  每個選項都會顯示預計費用，最便宜的會標為 **推薦**。執行前會先跳出一個確認對話框（可以關閉）。真正執行之前，擴充功能會再檢查一次，如果聊天視窗已經被重新開啟就會停止。
- **估價會考慮提示快取的狀態。**
  - 快取還沒過期時，用原本的模型壓縮最便宜。
  - 快取過期之後，換一個更便宜的模型大約能省一半。
  - 例如，一個 Claude Opus 5.5 工作階段有 400K token 的上下文：快取還在時約 $0.40；1 小時快取過期後，用原模型約 $3.52，換 Sonnet 5 約 $1.76。
- **選單裡還有：** **寫一份交接筆記**，適合你要切換到新任務的時候。對於新任務，開新工作階段比壓縮更合適。
- **提醒**（每一項都可以關閉）：
  - 在大型閒置聊天視窗的提示快取即將過期前，或是你關閉一個大型聊天視窗時，趁壓縮還便宜提醒你；
  - 壓縮之後，提醒你檢查關鍵規則是否還在。
- **Codex 聊天視窗：** 擴充功能會在 Codex 中開啟該對話，並複製好 `/compact` 供你貼上。
- **壓縮次數：** **詳細資料** 裡顯示 **已壓縮 N 次**（自動 + 手動）。壓縮兩次或以上後，如果上下文又變大了，會建議寫交接筆記並重新開始。當一個聊天視窗在 10 分鐘內壓縮了兩次，或是壓縮後立刻又進入「建議盡快處理」區間時，會用錯誤的顏色顯示 **可能陷入壓縮迴圈**。「兩次」是經驗值，不是精確測量的上限。

### 自己設定自動壓縮容量

Claude Code 會在上下文到達某個容量時自動壓縮，這發生在你還在工作的時候，快取是熱的，壓縮本身也便宜。你能選的是*容量設多少*。點擊聊天視窗 **詳細資料** 裡的 **自動壓縮：… ▾**，或是右鍵點擊一個聊天視窗，選擇 **設定自動壓縮閾值…**。

- 清單會把每個預設檔位換算成這個聊天視窗對應模型的容量（百分比和 token 數）、大約會在哪裡實際壓縮、依據有多強，並給出類似「每次呼叫約 $0.069，比預設省 45%」這樣的估算。**自訂…** 接受 100K 到 1M 之間的任意值，**查看參考說明** 會開啟這些數字背後的說明文件。
- **所有專案：** 如果聊天視窗是開啟的，擴充功能會在這個聊天視窗裡預先填入 `/autocompact <值>`；按 Enter 後 Claude Code 會立刻套用，並儲存到你的使用者設定。如果聊天視窗是關閉的，擴充功能會把 `autoCompactWindow` 寫進 `~/.claude/settings.json`。
- **僅這個專案：** 擴充功能會把 `autoCompactWindow` 寫進 `<專案>/.claude/settings.local.json`，它的優先權高於使用者設定。新開的工作階段會使用這個值；已經開啟的工作階段可能需要重新開啟。
- 擴充功能寫設定檔時只會改這一個鍵，保留你原有的格式，寫之前先備份，如果檔案解析不了就完全不寫。選擇 **保持預設** 會刪掉這個鍵。
- **Codex：** 擴充功能不會修改 `config.toml`。它會複製一行，例如 `model_auto_compact_token_limit = 217600`，開啟 `~/.codex/config.toml`，並請你把它貼到檔案開頭、任何 `[表]` 之前。

沒有任何廠商或論文給過「研究用 X%、寫程式用 Y%」這樣的標準答案。下面這些檔位是在廠商預設值、廠商評測設定、實務經驗和成本模型之間的折衷，依據一欄標出了每一檔有多可靠。

| 檔位 | 1M 視窗模型：設定值 → 約在這裡壓縮 | 200K 視窗模型 | Codex | 每次呼叫（Opus 5.5，1M）/ 相對預設 | 依據 |
| --- | --- | --- | --- | --- | --- |
| **保持預設**（給不想操心的人） | 不設 → 約 967K | 不設 → 約 167K | 90%（約 245K） | $0.126 / 100% | 強：廠商預設值，官方強烈推薦 |
| **寫程式（均衡）** | 400K（40%）→ 約 367K | 不設 | 90% | $0.069 / 約 55% | 中：一位實務者對 873 次壓縮的觀察數據（建構／理解程式碼約 300–450K）加實務經驗，沒有對照實驗 |
| **研究 / 檢索** | 250K（25%）→ 約 217K | 160K（80%）→ 約 127K | 80% | $0.056 / 約 44% | 中：Anthropic 自家的搜尋評測設定在 200K 觸發；DeepSeek-V3.2、Kimi K2.5 在視窗 80% 觸發。風險：更容易遺失最初的問題，建議寫進檔案 |
| **長時間自主執行** | 600K（60%）→ 約 567K | 不設 | 90% | $0.088 / 約 70% | 弱：折衷方案，沒有直接證據；最重要的是把目標和限制寫進檔案 |
| **省錢優先** | 200K（20%）→ 約 167K | 不設（調低也不省錢） | 80% | $0.052 / 約 41% | 中：成本模型加同一位實務者的成本最佳點（約 220K）。代價：壓縮次數約為預設的 7 倍，資訊損失最多 |

- **設定的值不等於實際壓縮點。** 實際會提前約 33K 壓縮（推算自官方「1M 約在 967K 壓縮」），所以「400K」其實約在 367K 壓縮。
- **在 200K 視窗的模型上，調低閾值幾乎不省錢**（每次約省 3%），所以只在看重品質時才這樣做。設定值不能低於 100K，所以這些模型只能用 50%–100%。
- **同一個值適用於所有模型。** 如果你在同一個作用範圍裡切換 1M 和 200K 模型，較小的視窗會把它封頂。
- **每次壓縮都會遺失細節。** 長期規則寫進 `CLAUDE.md`，換任務時開新工作階段，而不是壓縮。
- **成本模型：** 快取一直是熱的；每次呼叫新增約 3K token；壓縮後剩約 30K；摘要約為壓縮點的 4%（2K–20K）。價格依該聊天視窗的模型計算。
- **Claude Code 自己的建議：**「The auto setting picks a window tuned for your model and is strongly recommended for the best cost and performance. Overriding auto may result in high token usage, especially when resuming long sessions.」（auto 設定會為你的模型選一個調好的容量，為了最好的成本和效能，強烈推薦使用它；覆寫 auto 可能導致 token 用量偏高，尤其是接續長工作階段時。）它沒有說明原因。可能的原因：接續一個已經比新閾值還大的舊聊天視窗時會立刻壓縮，而且快取是冷的；閾值離聊天視窗一開始的大小太近，會反覆壓縮；摘要裡遺失的細節可能導致額外呼叫去重新讀取檔案。
- 如果為 Claude Code 設定了 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`，它會覆蓋以上所有設定。

完整的參考說明，附帶出處（其他工具的預設值、廠商評測、部落格建議和成本模型），見 [docs/compaction-threshold-guide.md](compaction-threshold-guide.md)（簡體中文）。

### 詳情

點擊一個智慧體可以看到它最近的步驟、最終結果（附複製按鈕）、它改過的檔案（點擊可以開啟）和它的工具錯誤。**開啟記錄檔案** 會開啟原始的工作階段記錄。

**詳細資料** 裡還有一列 **記錄檔案**：聊天視窗儲存在哪裡（主目錄會縮寫成 `~`），記錄檔案、它的子智慧體和檔案備份各有多大，以及 **在 Finder 中顯示**（Windows 上是檔案總管）和 **複製路徑** 按鈕。

### 用量與費用

- **上下文：** 相對自動壓縮點用了多少（例如「412K / 967K 自動壓縮」）、佔模型視窗的百分比（「佔 1M 視窗的 41%」），以及距自動壓縮還剩多少。進度列會隨著聊天視窗接近自動壓縮而填滿。
- **百分比和視窗都直接使用 Claude Code 和 Codex 自己的數字。** 百分比用 Claude Code 自己的公式：上下文 token 數（最近一次呼叫的輸入 + 快取寫入 + 快取讀取）÷ 上下文視窗，四捨五入。視窗來自 Claude Code 這次工作階段的費用記錄（能看出模型是不是用 1M 視窗執行的），否則用模型的標準視窗；Codex 則來自 Codex 的日誌。
- **自動壓縮發生在哪裡、為什麼：** 依序來自你的設定（這個專案的本機設定、這個專案的設定，或是你的使用者設定），否則是**實測**（記住這個模型上次在哪裡自動壓縮，由擴充功能記住），否則是官方預設值。提示會說明用的是哪一種。如果為 Claude Code 設定了 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`，它會比顯示的更早壓縮；擴充功能看不到 Claude Code 的環境變數。
- **上下文提示：** 當上下文較大、值得在下一個合適的節點處理時，會出現柔和的提示標籤（「可以考慮壓縮」、「建議盡快處理」）。它們從不改變燈的顏色。
- **提示快取：** 每個 Claude Code 聊天視窗的快取倒數（「快取：還剩 38 分鐘」）。
- **等值 API 費用：** 每個智慧體、每個聊天視窗，以及今日的總計。對於 Claude Code 聊天視窗，標題列顯示的是 Claude Code 自己的累計費用（「Claude Code 的統計」）；其餘的都是依 token 數與官網價目表估算出來的。訂閱方案不是這樣計費的，所以僅供比較參考。

### 額度與續跑

- 顯示 Claude Code 聊天視窗何時撞上工作階段、每週或模型額度，以及額度何時重置。
- 顯示 Codex 的 5 小時和每週用量百分比。
- 當一個聊天視窗或智慧體因額度用完、API 錯誤或被中斷而停止時，**複製續跑提示…** 會複製一份現成的提示詞或終端機命令（`claude --resume …`、`codex resume …`）。它還會估算重新讀取上下文需要多少費用。

### 聊天視窗存在哪裡，以及怎麼搬移

提示快取存放在 Anthropic 和 OpenAI 的伺服器上，不會佔用你電腦的空間。真正佔空間、並被反覆寫入的是聊天記錄、檔案備份、外掛和日誌。在一台測試機器上，每個 Claude Code 工作階段程序每小時寫入 23–78 MB、讀取 14–36 MB，佔用 300–400 MB 記憶體；`~/.claude/projects` 有 932 MB，`~/.codex` 裡外掛佔 298 MB、工作階段佔 52 MB。

這麼多寫入量對 SSD 壽命影響不大。真正的問題是系統磁碟的剩餘空間。搬走這些檔案能騰出空間，但不會減少記憶體佔用。

**智慧體監視器：儲存位置與占用**（在面板標題列的 **…** 選單裡，或命令選擇區裡）會顯示：

- Claude Code 的資料資料夾（`CLAUDE_CONFIG_DIR` 或 `~/.claude`），以及 `projects`、`file-history`、`plugins`、`skills`、`cache`、`backups`、`shell-snapshots` 和 `~/.claude.json` 各有多大；
- Codex 的資料夾（`CODEX_HOME` 或 `~/.codex`），它的子資料夾和資料庫檔案；
- 哪些項目已經是符號連結，以及它們指向哪裡；
- 每顆磁碟的剩餘空間；
- Claude Code 保留記錄多久（`cleanupPeriodDays`，不改的話是 30 天）。

大小統計在背景進行，只在頁面開啟時才計算，最多每 10 分鐘一次。

> **遷移方案僅供參考。** 這些方案是依你電腦上的路徑自動產生的，不是經過驗證的操作流程。請自己逐條核對路徑和命令，先備份重要資料，是否執行由你自己決定，執行的後果（包括資料遺失）由你自己承擔。本擴充功能依「現狀」提供，不附帶任何擔保。在頁面上，要先勾選確認，才能複製命令或把命令放進終端機。

它還會準備好把資料搬到別的資料夾的命令。預設建議是剩餘空間最多的非系統磁碟，你也可以自己選資料夾。

- **方案 A（推薦）：只搬最大的那個資料夾，留一個符號連結。** 對 Claude Code 是 `projects`，對 Codex 是 `sessions`。在 macOS 和 Linux 上，命令大致是這樣（實際產生的命令還會先檢查有沒有障礙）：

  ```sh
  mkdir -p '/Volumes/External/AI-Data/claude/projects' \
    && rsync -a ~/.claude/projects/ '/Volumes/External/AI-Data/claude/projects/' \
    && mv ~/.claude/projects ~/.claude/projects.bak \
    && ln -s '/Volumes/External/AI-Data/claude/projects' ~/.claude/projects
  # 確認一切正常後再刪除備份：rm -rf ~/.claude/projects.bak
  ```

  在 Windows 上用的是 `robocopy` 加目錄連接（`mklink /J`）。這些 Windows 命令還沒有在 Windows 上實際執行過。
- **方案 B（官方）：用 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME` 搬移整個資料夾。** 在 VS Code 裡，透過 Claude Code 擴充功能的 `claudeCode.environmentVariables` 設定來設定；在終端機裡則加進你的 shell 設定檔。換目錄後可能需要重新登入（未驗證）。

開始搬移前：

- 頁面會列出還開啟著的聊天視窗。請先關掉它們，搬移期間也不要開新的。
- 外接磁碟必須在啟動 Claude Code 或 Codex 之前就接好，不然連結會指向不存在的地方，工作階段會儲存失敗，或是在一個空資料夾裡重新開始。
- 不要用 iCloud 雲碟或 Dropbox 這類同步資料夾；持續寫入會和同步衝突。
- 在確認一切正常之前，保留 `.bak` 備份。

**擴充功能絕不會自己執行這些命令。** **複製命令** 只是複製它們，**在終端機中開啟** 會把它們打進一個新終端機、不按 Enter，方便你自己檢查後再執行。擴充功能會跟著資料走到哪裡：符號連結對它是透明的，`CLAUDE_CONFIG_DIR` 和 `CODEX_HOME` 也會被遵守。如果你完全不想儲存某個聊天視窗，Claude Code 的 `--no-session-persistence` 參數可以關閉記錄（這樣智慧體監視器就看不到那個聊天視窗了）。

### Claude Code 與 Codex

- **Claude Code**：VS Code 擴充功能、終端機或桌面應用程式裡的，包括子智慧體、背景智慧體和工作流程。
- **Codex**：VS Code 擴充功能、CLI 或桌面應用程式裡的，包括子智慧體和審閱執行緒。
- 兩者都可以在設定裡個別關閉。

### 終端機版

![終端機版用同樣的燈和同樣固定不變的順序](../images/terminal.png)

同一套監視邏輯也能在終端機裡執行。它包含在原始碼儲存庫裡，不在擴充功能套件裡，需要 Node.js 18 或更高版本（在 Node.js 24 上測試過）：

```sh
git clone https://github.com/cyuneo/cyuneo-agent-monitor.git
cd cyuneo-agent-monitor
node bin/agent-monitor.js --watch          # 原地重新整理；按 q 或 Ctrl+C 結束
node bin/agent-monitor.js --session 1a2b   # 詳細顯示一個聊天視窗：步驟、結果、檔案、錯誤、續跑
node bin/agent-monitor.js --json           # 以 JSON 形式輸出資料
```

其他選項還有 `--provider claude|codex`、`--window <minutes>`、`--here`（只顯示目前資料夾裡的聊天視窗）、`--today`、`--lang en|zh-cn|zh-tw|ko|ja` 和 `--no-color`。執行 `--help` 查看完整清單。

## 它讀什麼

一切都是唯讀的，只有一個例外由你自己觸發：當你設定自動壓縮閾值時，擴充功能可能會把 `autoCompactWindow` 這個鍵寫進 Claude Code 的某個設定檔（見[自己設定自動壓縮容量](#自己設定自動壓縮容量)）。當你在背景壓縮一個已關閉的聊天視窗時，是 Claude Code 自己把摘要寫進那個聊天視窗的記錄裡的。

| 檔案 | 用途 |
| --- | --- |
| `~/.claude/projects/<project>/<session>.jsonl` | Claude Code 聊天視窗（主對話） |
| `~/.claude/projects/<project>/<session>/subagents/…` | 子智慧體、背景智慧體和工作流程智慧體 |
| `~/.claude/projects/<project>/<session>/workflows/…` | 工作流程名稱、狀態和結果 |
| `~/.claude/sessions/*.json` | Claude Code 自己維護的執行中工作階段清單：哪些聊天視窗是開啟的，每一個是否正在忙碌，或是在等核准、回答或對話框。只讀取 `.json` 檔案，旁邊的 `.key` 檔案和 socket 一律不開啟。 |
| `~/.claude/settings.json`、`<專案>/.claude/settings.json`、`<專案>/.claude/settings.local.json` | 你的自動壓縮設定（`autoCompactWindow`、`autoCompactEnabled`）和 `cleanupPeriodDays` |
| `~/.claude/file-history/<session>` 以及 `~/.claude`、`~/.codex` 下的其他資料夾 | 只統計大小（用於記錄檔案那一列和儲存頁面），不會開啟檔案內容。 |
| `~/.codex/sessions/**/rollout-*.jsonl` | Codex 執行緒，包括子智慧體和審閱執行緒以及用量額度 |
| `~/.codex/session_index.jsonl` | Codex 執行緒標題 |
| `~/.codex/models_cache.json`、`~/.codex/config.toml` | Codex 上下文視窗和自動壓縮閾值 |

`CLAUDE_CONFIG_DIR` 和 `CODEX_HOME` 都會被遵守。你也可以用 `agentMonitor.claude.projectsDir` 和 `agentMonitor.codex.home` 指向其他位置。

擴充功能在 VS Code 自己的儲存空間裡保留一些很小的東西：哪些聊天視窗你已經看過、哪些提醒你關掉了、每個模型實測的自動壓縮點，以及它改過的設定檔的備份。只有在你點擊複製或壓縮相關操作時，它才會寫入剪貼簿。

## 隱私

- **擴充功能不會發出任何網路請求。** 它沒有遙測、沒有分析、沒有遠端內容，不會因為它而有任何東西離開你的電腦。
- **唯一的例外是在背景壓縮一個已關閉的聊天視窗**，而且只在你確認之後。這時擴充功能會執行你本機的 Claude Code（`claude -p --resume <session> --model <model> --output-format json "/compact …"`）。Claude Code 會像你自己使用它時一樣連線到 Anthropic，用量會計入你的方案或 API 帳單。
- **壓縮一個開啟中的聊天視窗，或是設定它的自動壓縮閾值，都只是把文字放進它的輸入框**（`/compact …` 或 `/autocompact …`）。在你按下 Enter 之前，什麼都不會傳送。（聊天視窗沒開啟，或是只對這個專案生效時，閾值改為寫進設定檔，見[它讀什麼](#它讀什麼)。）
- **搬移資料由你自己決定。** 儲存頁面只產生命令，擴充功能絕不會自己執行；**在終端機中開啟** 也不會替你按 Enter。
- **參考說明連結** 只有在你點擊時，才會在瀏覽器裡開啟 GitHub 上的一個頁面。
- **你的對話內容留在本機。** 聊天標題、步驟和結果只會顯示在你自己的 VS Code 裡。
- **這些數字是給你看的，不是給模型看的。** 上下文大小、快取倒數和費用永遠不會傳給模型。

## 上下文與壓縮小提示

這些提示來自對公開研究和官方文件的整理。完整筆記與出處見 [docs/research-context-compaction.md](research-context-compaction.md)（簡體中文）。關於怎麼選自動壓縮容量，見 [docs/compaction-threshold-guide.md](compaction-threshold-guide.md)（簡體中文）和[自己設定自動壓縮容量](#自己設定自動壓縮容量)。

1. **不要為了保險就壓縮。** 如果任務進行順利，1M 上下文的模型還在 200K token 左右以下，就不用管它。低於約 50K 時幾乎沒什麼可省的，壓縮只會遺失細節。
2. **在節點處壓縮，並說明要保留什麼。** 好的時機是探索階段結束，或是一個子功能做完了，而不是任務進行到一半。用 `/compact 請保留：目標、決定及原因、未解決的問題、檔案路徑，以及「不要推送」之類的約束`。超過約 500K 時，在下一個節點處理，不要等自動壓縮在任務中途觸發。
3. **把長期規則寫進檔案。** 用專案根目錄的 `CLAUDE.md`（Codex 用 `AGENTS.md`）。只在對話裡說過的規則，壓縮後常常會遺失。
4. **換任務就開新工作階段。** 用 `/clear`，需要的話先寫一份交接筆記，並且自己先讀一遍再放心使用。如果走錯了方向，用 `/rewind` 而不是壓縮。
5. **趁快取還在時壓縮。** 壓縮要重新讀取整段上下文，快取還在時這樣做很便宜。參見[壓縮按鈕](#壓縮按鈕可選模型帶費用估算)一節的例子。
6. **留意壓縮次數。** 壓縮兩次或以上後（這是經驗值，不是精確的上限），如果還有很多要做，就寫一份交接筆記重新開始。每次壓縮後，都要檢查關鍵約束——尤其是提交、推送和刪除權限——是否還在。
7. **為子智慧體開 1 小時快取前先想清楚。** 每次快取寫入都會貴 60%（2 倍而不是 1.25 倍的輸入價格）。只有子智慧體經常停頓超過 5 分鐘時才划算。撞額度的停頓通常要幾個小時，比 1 小時快取還長。

## 已知限制

- **記錄格式可能會變。** Claude Code 和 Codex 的記錄格式是內部格式，任何更新都可能改變它。擴充功能讀不懂的行會被跳過。
- **步驟可能會延遲。** 記錄是在每次模型呼叫後寫入的，所以在一段長時間的思考中，顯示的步驟是最後寫入的那一個。
- **「需要你處理」只有在應用程式回報狀態時才是確定的。** 也就是說，只有能在 `~/.claude/sessions` 裡回報即時狀態的 Claude Code 版本。更早的 Claude Code 版本和 Codex 依賴上面說的推測，而且 Codex 幾乎不會把等待核准和錯誤寫到磁碟上。
- **費用是估算值。** 它們依提示中顯示日期的官網價目表計算，價格會變。有些模型，例如 Codex 的審閱模型，沒有公開價格。
- **不會顯示 Claude Code 的用量百分比。** Claude Code 不會把它保存到本機檔案，所以對於 Claude，擴充功能只能顯示額度觸發和重置時間。
- **分頁跟隨有盲點。** 它靠分頁標題比對 Claude Code，靠對話 ID 比對 Codex。側邊欄檢視（而不是編輯器分頁）裡顯示的聊天視窗無法被偵測到。
- **可選模型的背景壓縮只支援 Claude Code。** Codex 在自己內部壓縮。一個聊天視窗開啟時不能在背景壓縮。
- **Claude Code 的環境變數對擴充功能不可見。** `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 和 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 可能讓 Claude Code 在跟介面顯示不同的地方壓縮。只有模型自動壓縮過一次之後，才會出現實測值。
- **每個 VS Code 視窗各自獨立讀取記錄。**
- **Windows 的遷移命令還沒有在 Windows 上實測過。** 儲存位置頁面產生的 `robocopy` 和 `mklink /J` 命令只核對過文字。執行前請先看一遍，確認一切正常之前不要刪掉 `.bak` 備份資料夾。
