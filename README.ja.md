# CYUNEO Agent Monitor

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [한국어](README.ko.md) · **日本語**

すべてのAIコーディングのチャットを、ターミナルのすぐ隣で一箇所から確認できます。どのエージェントが動いているか、どれが対応待ちか、各コンテキストがどれくらい埋まっているか。Claude Code、Codex、GitHub Copilot Chatに対応し、Gemini CLIとQwen Codeにはプレビューとして対応しています。

> **プレビュー版（0.5.0）。** おかしな点を見つけたら、[GitHub Issues](https://github.com/cyuneo/cyuneo-agent-monitor/issues)で報告してください。

## なぜ作ったのか

Claude CodeとCodexは今や、複数のエージェントを同時に動かします。サブエージェント、バックグラウンドエージェント、ワークフロー全体まで。ところがVS Codeでは、その作業のほとんどが見えません。

- **誰が何をしているか見えない。** エージェントビューは自分で開かないと表示されないため、承認待ちのエージェントが誰にも気づかれずに止まっていることがあります。
- **コンテキストが静かに埋まっていく。** 自動圧縮が都合の悪いタイミングで始まったり、長い会話が内容を忘れ始めたりして、ようやく気づきます。
- **少し離れるとキャッシュが切れる。** 1時間後に戻ると、次のメッセージでコンテキスト全体を通常料金で読み直すことになります。
- **使用量の上限で作業が途中で止まる。** エージェントが止まったら、自分で気づき、リセットを待ち、手動で再開させなければなりません。

## できること

- **すべてのチャットをひと目で。** ターミナルの隣のパネルに、開いているチャットと最近のチャットがステータスランプ付きで並びます。クリックすると、その中のエージェント、それぞれが進めている手順、トークン数と費用がわかります。
- **その場所へすぐ移動。** **移動**をクリックするかチャットをダブルクリックすると、そのチャットが動いている場所を表示します: Claude CodeやCodexの拡張機能、Copilot Chatのそのチャット、または動いているVS Codeのターミナルで、別のVS Codeウィンドウにあっても移動できます（macOSではTerminal.appやiTerm2のタブにも）。
- **自分の出番がすぐわかる。** 承認や回答を待っているチャットはマゼンタのランプで知らせます。完了やエラーもそれぞれの色で表示され、ステータスバーにも出ます。
- **席を離れていても知らせてくれる。** チャットが対応を待ち始めると、VS Codeやシステムの通知でお知らせします。サウンドを鳴らすこともできます。スマートフォンやチームのチャット（ntfy、Bark、ServerChan、Feishu、DingTalk、WeCom、Telegram、Discord、Slack）に短いメッセージを送ることもでき、エラーや使用量の上限も知らせます。おやすみ時間を決めておけば、夜は静かです。
- **上限に近づいたら先に知らせる。** Codexの使用量が90%に達したときにアラートを出します。設定をオンにすれば、今日の推定コストが決めておいた予算を超えたときや、チャットのコンテキストが自動圧縮に近づいたときにも知らせます。
- **コンテキストを管理できる。** 各チャットのコンテキストの埋まり具合を確認し、パネルから直接圧縮し（安いモデルも選べ、先に費用の見積もりを確認できます）、自動圧縮のタイミングを自分で決め、キャッシュが切れる前に通知を受けられます。
- **使用量の上限のあとも続けられる。** 上限がいつリセットされるかを表示し、再開用のプロンプトやコマンドを用意するので、コピーするだけで使えます。
- **これまでの使用量がわかる。** 使用量の履歴ページで、Claude CodeとCodexの直近30日の1日ごとの推定コストとトークン数を、モデル別にも確認できます。
- **チャット記録の保存場所がわかる。** Claude CodeとCodexのチャットが使っている容量を表示し、別のディスクへ移すための参考コマンドも示します。

対応ツールがすでにコンピューター上に書き込んでいる記録を読み取るだけで、データも収集しません。**ネットワークアクセス**を許可しない限り（既定はオフ）、拡張機能自体はネットワークに接続しません。現在これを使うのはプッシュ通知だけです。

## 対応ツール

- **Claude Code**と**Codex**: VS Code拡張機能、コマンドライン、デスクトップアプリで、サブエージェントを含みます。
- **GitHub Copilot Chat**: VS Codeに組み込まれたチャットで、エージェントモードを含みます。
- **Gemini CLI**と**Qwen Code**は**プレビュー**です。公開されている記録形式をもとに作っており、まだ実際のセッションでは確認していません。おかしな点があれば、[GitHub Issues](https://github.com/cyuneo/cyuneo-agent-monitor/issues)で報告してください。

インストールされていないツールはスキップされ、各ツールは設定で個別にオフにできます。ツールによって見える内容は少しずつ異なります。たとえばCopilot Chatではドル建てのコストの代わりにCopilot creditsが表示され、Gemini CLIの状態は推測です。圧縮、使用量の履歴、今日の合計コスト、保存場所のページはClaude CodeとCodexのみが対象です。詳しくは完全ガイドの[対応ツール](docs/GUIDE.ja.md#対応ツール)をご覧ください。

## 使い始める

1. 上の**VS Codeにインストール**をクリックするか、拡張機能ビューで**CYUNEO Agent Monitor**を検索します。
2. 下部パネルでTerminalの隣にある**エージェントモニター**タブを開きます。
3. 一覧のチャットをクリックすると、そのチャットのエージェントが表示されます。

すべての機能、コマンド、設定の詳しい説明は**[完全ガイド](docs/GUIDE.ja.md)**をご覧ください。

## 必要環境

- VS Code 1.94以降。
- 同じコンピューター上で使う、対応ツールのいずれか1つ以上: Claude CodeまたはCodex（VS Code拡張機能、コマンドライン、またはデスクトップアプリ）、VS CodeのGitHub Copilot Chat、Gemini CLI、Qwen Code。
- 閉じたチャットをバックグラウンドで圧縮するには、Claude Codeのコマンドラインも必要です。拡張機能はPATH上の`claude`をまず探し、次にインストール済みのClaude Code拡張機能内を探します。`agentMonitor.claude.cliPath`を設定することもできます。
- 自動テストはmacOS、Windows、Linuxで実行しています（Node.js 22、LinuxではNode.js 20も）。VS Code上で実際に使ってのテストは、今のところmacOSでしか行っていません。

## プライバシー

- テレメトリはなく、**ネットワークアクセス**を許可しない限り（既定はオフ）ネットワークにも接続しません。現在これを使うのはプッシュ通知だけです。会話の内容はお使いのコンピューターから出ません。
- プッシュ通知はオプションで、既定はオフです。オンにすると、設定したサービスに短いメッセージだけを送ります。内容はプロジェクトフォルダー名と状態で、許可した場合はチャットのタイトルとサブエージェント名も加わります。それ以外がコンピューターの外に出ることはありません。
- 使用量の履歴はお使いのコンピューター上で計算し、サウンドはシステム自身が再生します。どちらも外部には何も送りません。
- **移動**は、使ったときだけコンピューターで実行中のプロセスを調べ、チャットが動いている場所を探します。そのためにチャットの内容を読むことはなく、外部には何も送りません。
- ファイルを変更したりClaude Codeを実行したりするのは、ご自身が確認した後だけです（[免責事項](#免責事項)を参照）。
- 詳しくはガイドの[読み取る内容](docs/GUIDE.ja.md#読み取る内容)と[プライバシー](docs/GUIDE.ja.md#プライバシー)をご覧ください。
